# 8 位模型机三条机器指令替换设计指导

## 1. 设计目标

本设计以 `d:\jizu\8BitCPU_DESIGN_TFT_M\8BitCPU_DESIGN_TFT` 中的 `CPU5A` 工程和课程讲义为依据。这里的任务是“替换三条机器指令”，不是“扩展五条机器指令”：保留原有五个操作码位置和五条指令的总数量，只替换其中三个功能，不增加操作码、不增加指令入口。

保留 `IN` 和 `OUT`，将 `ADD`、`STA`、`JMP` 分别替换为 `SUB`、`AND`、`XOR`。这样实验箱仍可通过键盘输入数据、通过 LCD/LED 观察结果，同时能够验证算术运算和逻辑运算两种 ALU 工作模式。

## 1.1 Quartus 工程文件和修改边界

先在 Quartus 中打开 `CPU5A.qpf`，确认顶层实体为 `CPU5A`。不要直接用文本编辑器改写 `.bdf`，应在 Quartus Block Editor 中打开后保存；`.bdf` 是图形原理图文件，手工改写容易破坏连线和符号信息。

| 文件 | 作用 | 本设计是否修改 |
|---|---|---|
| `CPU5A.qsf` | 工程、器件、引脚和源文件清单 | 一般不改；只用于确认顶层和器件 |
| `CPU5A.bdf` | 顶层 FPGA 接口、时钟、复位、输入和 LCD 连接 | 不改接口；仅在需要改 OUT 输出来源时通过图形编辑器改连线 |
| `CPU5.bdf` | CPU 数据通路，含 `R0、R1、DR1、ALU` 等部件和控制端 | 通常不改；确认 `R1` 的总线输入端 `LDR1` 已连接 |
| `ALU_MD.bdf` | ALU 模块的图形连接和 `M、S3..S0、/CN` 控制线 | 通常不改；确认控制线没有被悬空或接错 |

| `decoder_A.bdf` | 微指令 A 字段译码，产生寄存器装入/总线输出控制 | 通常不改；确认存在 `LDR1` 和 `R1_B` |
| `decoder_B.bdf` | 微指令 B 字段译码，产生总线输出控制 | 通常不改；确认 R0/DR1 等输出选通可用 |
| `decoder_C.bdf` | 微程序分支、测试和 `LDPC` 等控制 | 不改分支结构；XOR 微程序不能使用 `LDPC` |
| `decoder_D.bdf` | `A9/A8` 控制台、RAM、LED 等选通译码 | 不改；保留 KRD/KWE/RP 控制台流程 |
| `uPC.bdf`、`uPC22.bdf` | 微地址寄存器和微地址分支 | 只在入口地址或分支逻辑确实需要改变时修改；本方案优先复用原入口 |
| `uA_ROM.qip`、`uP_ROM.qip` 及其 MIF | 微程序控制存储器 | 必须先恢复；确认实际 `LPM_FILE` 后只修改对应 MIF |
| `REGS_MD.bdf`、`REGS_MD2.bdf` | R0/R1/R2 和 DR0/DR1 的寄存器组 | 通常不改；SUB 结果必须连接到 R1 的 `LDR1` |

## 2. 替换后的指令集

### 2.1 操作码分配

操作码仍使用指令高 4 位，低 4 位暂不参与译码。替换关系如下：

| 操作码 | 原指令 | 新指令 | 指令长度 | 功能 |
|---|---|---|---|---|
| `0H` | IN | IN | 1 字节 | `INPUT -> R0` |
| `1H` | ADD | SUB | 2 字节 | `R0 - [addr] -> R1` |
| `2H` | STA | AND | 2 字节 | `R0 AND [addr] -> R0` |
| `3H` | OUT | OUT | 2 字节 | `[addr] -> OUT` |
| `4H` | JMP | XOR | 2 字节 | `R0 XOR [addr] -> R0` |

这里的 `[addr]` 表示先用第二字节作为 RAM 地址，再读取该地址中的 8 位操作数。三条替换指令均采用原 `ADD` 的双字节、直接内存寻址格式，因此不需要增加数据通路。

### 2.2 机器码格式

```text
单字节：OP 0000
双字节：OP 0000，ADDR
```

示例：

```text
00       ; IN
10 0A    ; SUB [0AH]，结果写入 R1
20 0B    ; AND [0BH]
40 0C    ; XOR [0CH]
30 0D    ; OUT [0DH]
```

## 3. 数据通路和 ALU 控制

本工程的 `ALU181A.v` 给出了实际运算编码。微程序中只需要修改 `S3..S0、M、/CN`，其余数据通路沿用原 `ADD`、`OUT` 微程序。

| 运算 | `M` | `S3..S0` | `/CN` 建议值 | 说明 |
|---|---:|---|---:|---|
| 减法 | `0` | `0110` | `1` | `F=A-B-CN`，`CN=1` 时为 `A-B-1`，需按工程的低有效进位约定核验 |
| 逻辑与 | `1` | `1011` | `1` | `F=A AND B`，不使用进位 |
| 异或 | `1` | `0110` | `1` | `F=A XOR B`，不使用进位 |

SUB 特别要求使用两个不同的寄存器：把 `R0` 作为被减数寄存器，把 `R1` 作为结果寄存器；从 RAM 读出的减数先装入 `DR1`。执行阶段的数据流为：

```text
PC -> AR -> RAM[addr] -> BUS -> DR1
R0 -> ALU A
DR1 -> ALU B
ALU F -> BUS -> R1
```

减法的 `/CN` 必须通过一次单步实验确认。若下载后出现 `R0-操作数-1`，将减法微指令的 `/CN` 由 `1` 改为 `0`，再用 `10H-01H` 验证结果是否为 `0FH`。

## 4. 微程序修改方案

### 4.1 译码入口

保留原微程序控制器的 `P(1)` 分支结构和五个固定入口，只改变入口对应的微程序内容：

| 指令入口 | 原入口含义 | 修改后含义 |
|---|---|---|
| `10(八进制)` | ADD | SUB |
| `20(八进制)` | STA | AND |
| `30(八进制)` | OUT | OUT，保持不变 |
| `40(八进制)` | JMP | XOR |

操作码译码仍然直接使用 `IR7..IR4`。不要改变 `P(1)` 测试和取指入口，否则 `IN/OUT` 及控制台读写流程也会受到影响。

### 4.2 SUB 微程序

SUB 可以复制原 ADD 的“取地址、读操作数、装入 DR1、R0 送入 ALU、ALU 运算”流程，只把最后的 ALU 控制字段改成减法，并将运算结果的总线输入选通改为 `R1` 的装入信号。不得将结果重新写回 R0，否则就没有使用两个不同的寄存器。

```text
取指结束 -> 读取 SUB 的地址字节 -> AR 装入 addr
          -> RAM[addr] -> BUS -> DR1
          -> R0 -> ALU A，DR1 -> ALU B
          -> M=0，S=0110，/CN 按上表设置
          -> ALU -> BUS -> R1
          -> 返回公共取指入口
```

### 4.3 AND 微程序

复制原 ADD 的取地址和读 RAM 部分，执行阶段设置 `M=1、S=1011`，把 ALU 结果经总线写回 R0。原 STA 的入口不再执行 RAM 写操作，`WE` 必须保持读状态或无效状态，不能产生写脉冲。

### 4.4 XOR 微程序

复制原 ADD 的取地址和读 RAM 部分，执行阶段设置 `M=1、S=0110`，把 ALU 结果经总线写回 R0。原 JMP 的 `LDPC`、`PC_B` 控制信号必须清除，避免 XOR 错误地改变程序计数器。

### 4.5 24 位微指令填写规则

按照讲义表 1-1 的字段顺序填写 LPM_ROM 的 MIF：

```text
bit 23..20 : S3 S2 S1 S0
bit 19     : M
bit 18     : /CN
bit 17     : WE
bit 16..15 : A9 A8
bit 14..12 : A 字段
bit 11..9  : B 字段
bit 8..6   : C 字段
bit 5..0   : 下一微地址 uA5..uA0
```

具体 A/B/C 编码必须沿用现有 `decoder_A.bdf`、`decoder_B.bdf`、`decoder_C.bdf` 的定义。讲义中的字段编号存在排版错位，实际填写时以工程 ROM 的 24 位拼接顺序和现有 MIF 为准。最稳妥的做法是复制原 ADD 对应微地址行，只修改 ALU 字段；复制原 STA/JMP 行时，必须逐项检查 `WE、LDPC、PC_B`，不能只修改操作码名称。

#### 4.6.3 修改三条替换指令的微程序

1. 按 MIF 文件头解释地址进制。讲义中的微地址若使用八进制，必须先换算成 MIF 的 `ADDRESS_RADIX`，不能直接把八进制地址当十进制或十六进制地址。
2. 以原 `ADD` 微程序为模板制作 `SUB`：保留取第二字节、访问 RAM、装入 `DR1` 的节拍；执行节拍使用 `M=0、S=0110`，并确认 `ALU -> BUS -> LDR1`，没有 `LDR0`。
3. 以原 `ADD` 的取数部分为模板制作 `AND`：执行节拍使用 `M=1、S=1011`，并通过 `LDR0` 把结果写回 R0；原 `STA` 的 RAM 写使能 `WE` 必须清除。
4. 以原 `ADD` 的取数部分为模板制作 `XOR`：执行节拍使用 `M=1、S=0110`，通过 `LDR0` 写回 R0；原 `JMP` 的 `LDPC、PC_B` 必须清除。
5. 每条替换指令的最后节拍都回到公共取指入口。不要改 `P(1)` 取指分支、控制台 `P(4)` 分支、KRD/KWE/RP 流程或五个操作码的入口数量。
6. `ALU181A.v` 的端口名是 `CN`，不是 `/CN`；该 HDL 在 `M=0、S=0110` 时计算 `A-B-CN`，在 `M=1` 的逻辑运算时不使用 `CN`。因此微指令字段显示为 `/CN` 还是 `CN`，必须以完整工程中的译码器极性为准，不能只按指导书示例填写。SUB 的 `CN` 极性应使用 `10H-01H` 单步实测确认。

### 4.7 是否需要修改 HDL 和原理图

本方案不需要新增 Verilog 模块，也不需要修改 `ALU181A.v`：该文件已经实现 `M=0,S=0110` 的减法、`M=1,S=1011` 的 AND 和 `M=1,S=0110` 的 XOR。必须修改的是微程序 ROM 的数据，以及必要时在 Block Editor 中确认 SUB 结果确实接到 R1 的 `LDR1` 控制线上。

只有在希望 OUT 直接显示 R0 的最终结果时，才打开 `CPU5A.bdf`/其下层输出模块，在图形编辑器中把 OUT 的数据源由 RAM 数据路径改为 R0 总线路径；这不是三条替换指令本身的必需修改。若不改 OUT，必须预先在 OUT 的 RAM 地址中写入期望值，并用 LCD 上的 R0/R1 验证运算结果。

### 4.8 MIF 修改示例

下面以讲义表 1-3 中的微指令 `919A01` 为例。它可以作为原 ADD 最后一个 ALU 执行节拍的模板。假定 MIF 使用 24 位数据、十六进制地址和十六进制数据，文件结构类似：

```mif
WIDTH=24;
DEPTH=64;
ADDRESS_RADIX=HEX;
DATA_RADIX=HEX;

CONTENT BEGIN
    00 : 018110;
    01 : 01ED82;
    ...
    06 : 919A01; -- 原 ADD 执行节拍
    ...
END;
```

按本工程 `ALU181A.v` 的定义，`919A01` 的字段可拆成：

```text
S=1001，M=0，/CN=0，WE=0，其他 A/B/C/uA 字段保持不变
```

`M=0、S=1001` 是算术加法类操作。若把该节拍改成 SUB，并且希望保持其余控制信号不变，只需将 ALU 字段改为 `M=0、S=0110`：

```mif
    06 : 619A01; -- SUB：S=0110，M=0，其余字段沿用原行
```

这里的变化是：

```text
原值 919A01 -> 新值 619A01
原 S=1001  -> 新 S=0110
M、/CN、WE、A9/A8、A/B/C、uA 保持不变
```

如果要把同一个 ALU 执行模板改成 AND 或 XOR，示例值分别为：

```mif
    06 : B99A01; -- AND：M=1，S=1011
    06 : 699A01; -- XOR：M=1，S=0110
```

实际工程中不能把三行同时写在地址 `06`，这里只是展示三种替换结果，最终应根据指令入口分别放在 SUB、AND、XOR 的执行微地址。

重要：上述示例只改变 ALU 运算字段，并不自动保证结果写入 R1。SUB 的最后一个节拍还必须使用译码器中对应 `LDR1` 的 A 字段编码，并且不能同时产生 `LDR0`。应在 `decoder_A.bdf` 或 `REGS_MD.bdf` 中确认该编码；如果原 ADD 行的 A 字段是 `LDRi`，还要确认 `IR` 中的寄存器选择位确实选中 R1。修改后建议先用 `10H-01H` 单步验证 `R0` 不变、`R1=0FH`，再继续验证完整程序。

修改 MIF 时只改 `CONTENT` 中对应地址右侧的 6 位十六进制数据，保留文件头、未修改地址和 `END;`。如果原文件的 `ADDRESS_RADIX` 不是 `HEX`，必须按原文件的地址进制填写地址；讲义中的微地址常用八进制，不能直接把讲义地址当作 MIF 地址。

## 5. 建议的验证程序

将以下程序写入 RAM。为便于观察，输入 `5AH`，内存中的三个操作数分别为 `12H、0FH、33H`，结果存放地址为 `0DH`，但不使用 STA，直接让 OUT 读取最终结果。

| 地址 | 内容 | 汇编 | 说明 |
|---:|---:|---|---|
| `00H` | `00H` | `IN` | 输入到 R0 |
| `01H` | `10H` | `SUB [0AH]` | `R0-12=48H`，结果写入 R1 |
| `02H` | `0AH` |  | 地址字节 |
| `03H` | `20H` | `AND [0BH]` | `48 AND 0F=08H` |
| `04H` | `0BH` |  | 地址字节 |
| `05H` | `40H` | `XOR [0CH]` | `08 XOR 33=3BH` |
| `06H` | `0CH` |  | 地址字节 |
| `07H` | `30H` | `OUT [0DH]` | 输出地址 `0DH` 的数据 |
| `08H` | `0DH` |  | 地址字节 |
| `0AH` | `12H` | 数据 | SUB 操作数 |
| `0BH` | `0FH` | 数据 | AND 操作数 |
| `0CH` | `33H` | 数据 | XOR 操作数 |
| `0DH` | `3BH` | 数据 | 若不执行 STA，该单元需预置 `3BH` 供 OUT 读取 |

由于原 `OUT` 的语义是“从 RAM 地址读出并送输出口”，而本方案删除了 `STA`，上表的 `OUT [0DH]` 只能在地址 `0DH` 预置 `3BH` 时验证显示通路，不能证明运算结果已经写回 RAM。可采用下面两种验收路径之一：

1. 保持原 OUT：预先把 `0DH` 写成预期值 `3BH`，用 OUT 验证显示通路，同时用 LCD 上的 R0 验证运算结果。
2. 将 OUT 的微程序最后一步改为“R0 -> OUT”，这样可以直接显示运算结果；该方式改变了 OUT 的数据源，应在报告中单独说明。

推荐第 2 种方式，因为它不依赖 STA，能直接在实验箱上显示三条替换指令的最终结果。若坚持完全保留原 OUT 行为，则应在报告中采用第 1 种方式，并通过 LCD 上的 `R0` 观察 `3BH`。

## 6. 实验箱操作步骤

1. 在 Quartus 中打开 `CPU5A` 工程，备份原微程序 ROM 的 MIF 文件。
2. 只修改指令译码入口和三条替换指令的微程序，不修改顶层 `CPU5A.bdf` 的时钟、复位、输入和 LCD 接口。
3. 重新生成 LPM_ROM，并编译工程生成新的 SOF 文件。
4. 下载 FPGA 后按复位键，确认 `RST` 释放为高电平；`CLK0` 选择讲义规定的 CPU 时钟。
5. 选择 `SWA/SWB=01`，用输入键和单步键把上表机器码及数据写入 RAM。
6. 选择 `SWA/SWB=00`，每两个单步脉冲检查 RAM 内容，重点确认地址字节没有错位。
7. 选择 `SWA/SWB=11`，输入 `5AH`，逐节拍观察 `PC、AR、IR、BUS、DR1、R0、R1、ALU、MC`。
8. 在 SUB 执行末尾确认 `R0=5AH` 且 `R1=48H`，证明减法使用了两个不同寄存器；AND 执行末尾确认 `R0=08H`，XOR 执行末尾确认 `R0=3BH`。
9. 在 OUT 执行期间确认输出端或 LCD 显示 `3BH`，并记录每条微指令的微地址和控制字段。

## 7. 常见错误检查

| 现象 | 优先检查项 |
|---|---|
| 执行 SUB 后少 1 | `/CN` 电平与工程低有效约定不一致 |
| SUB 后 R0 被覆盖或 R1 不变 | 结果回写选成了 `R0`，应选择 R1 的装入信号 |
| AND/XOR 结果不变 | `M` 没有置 1，或 ALU_B 没有打开 |
| 执行新指令后 PC 跳转 | 复制 JMP 微程序时遗留 `LDPC` 或 `PC_B` |
| RAM 内容被破坏 | 复制 STA 微程序时遗留 `WE=1` |
| 指令地址错位 | 把双字节指令当成单字节，或 PC 没有连续加 1 |
| LCD 有结果但 OUT 无显示 | OUT 仍从 RAM 取数；采用“预置 RAM”验证，或按本指导修改 OUT 数据源 |
