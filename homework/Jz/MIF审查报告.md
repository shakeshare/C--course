# 两份 MIF 文件审查报告

## 1. 审查范围与结论

审查依据：用户提供的讲义截图、讲义中的表 1-1/表 1-2/表 1-3、微程序流程图，以及 `RAM_1.MIF` 和 `ROM_5.MIF` 的完整内容。

**核心结论：结合你补充的修改位置，RAM 中的 `12`、`26` 可以视为已经替换后的机器指令编码；但 ROM 的修改控制流仍存在确定错误：`09 -> 19 -> 20`，而微地址 `20` 在当前 MIF 中没有有效微指令。**

按你的说明，ROM 的实验修改点是 `09、0A、19、20`，RAM 的实验修改字节是 `12、26`。因此不能再简单地把 RAM 中的 `12`、`26` 判定为原始 ADD、STA。需要重点检查的是：这两个新操作码是否正确进入复用后的入口，以及 ROM 新增/修改的微地址是否都实际写入了有效控制字。

`RAM_1.MIF` 的格式和数据内容本身没有发现语法问题，但其中的程序仍按原来的双字节 ADD/STA 形式排列。若 NOT 是一条不带地址的单字节指令，现有程序会发生 PC 对齐错误；若 MOV 也改变了指令长度或操作数格式，同样会发生对齐错误。

## 2. 文件格式检查

### RAM_1.MIF

- `WIDTH=8`、`DEPTH=256`，地址和数据均使用十六进制，格式正确。
- 00～0B 地址有显式内容，00C～0FF 用 00 填充，范围没有重叠。
- 以讲义的五条指令编码解释时，程序区可读为：

  ```text
  地址       00  01  02  03  04  05  06  07  08  09  0A  0B
  数据       00  12  0A  26  0B  30  0B  40  00  00  D5  AC
  ```

  按你补充的实验修改，程序区应解释为：

  ```text
  00: IN
  01: 12 0A    修改后的指令 1，操作数/地址为 0A
  03: 26 0B    修改后的指令 2，操作数/地址为 0B
  05: 30 0B    OUT 0B
  07: 40 00    JMP 00
  0A: D5       数据
  0B: AC       数据
  ```

  因此，RAM 的字节布局仍然是两个双字节指令：修改指令 1 使用 `12 0A`，修改指令 2 使用 `26 0B`。如果你的 NOT、MOV 仍复用原 ADD、STA 的双字节格式，则 PC 对齐本身没有问题；操作数是否被使用，要由对应微程序决定。

- 00～1A 有微指令，1B～3F 用 `000000` 填充，范围没有重叠。
- 没有发现 MIF 语法层面的错误。

## 3. 微指令位域审查

按讲义表 1-1，24 位微指令拆分为：

```text
S3 S2 S1 S0 M Cn WE | A9 A8 | A(15..13) | B(12..10) | C(9..7) | uA(6..1)
```

### 对 ADD 替换为 NOT 的审查

1. 你指出的 `09` 当前微字是 `01ED99`，其字段为 `A9A8=3、A=B=C=6、uA=19`，说明该位置把控制流送往 `19`。
2. `0A` 当前微字是 `019201`，字段为 `A=1、B=1、C=0、uA=01`，执行后回到取指/分派入口。这个字本身可以作为一个完成操作后回取指的微步骤，但它不能替代 NOT 的实际 ALU 运算；NOT 的 ALU 控制必须出现在此前的有效微地址中。
3. 如果 `12 0A` 是复用 ADD 入口的双字节 NOT 指令，那么 PC 对齐是成立的；但 `0A` 是否只是占位操作数，必须由微程序明确处理，不能仅凭机器码判断。
4. 原 ADD 的算术微地址 06 仍为 `919A01`。如果 NOT 要实现 `R0 <- NOT(R0)`，应确认复用入口最终经过的 ALU 控制字段确实选择 NOT，而不是仍执行 ADD 的 `ALU=24h`。

### 对 STA 替换为 MOV 的审查

1. 你指出的 `19` 当前微字是 `01B220`，字段为 `A=3、B=1、C=0、uA=20`。因此修改后的 MOV 路径确实被安排到了 `19`，但下一步跳到 `20`。
2. 当前 MIF 中 `20` 落在 `[1B..3F] : 000000` 范围内，实际微字为 `000000`。它的 `WE=0`、A/B/C 均为 0、`uA=00`，没有完成 MOV 数据传送；如果微地址直接按 `uA` 转移，它只会回到 00，形成错误的空操作/循环。
3. 因此，**ROM 的 MOV 控制流目前不完整，必须在地址 20 写入有效微指令**，而不能只在 19 设置 `uA=20`。
4. `MOV` 的正确微指令取决于实验定义：
   - 若定义为 `MOV R0, R1/R2`，目标应是寄存器写入，不能使用 STA 的 `WE=1` RAM 写入路径；
   - 若定义为 `MOV addr`，即把 R0 写入内存，那么它在微操作上可能接近 STA，但仍需确认操作码的地址字节、目标地址寄存器和写使能时序。
5. 仅仅把助记符 STA 改写成 MOV，而不改变对应的源/目的寄存器控制信号，不构成 MOV 实现。

### 修改后的确定性跳转问题

根据当前 MIF 的实际值：

```text
09: 01ED99 -> uA=19
19: 01B220 -> uA=20
20: 000000 -> uA=00，且 WE=0、无有效数据通路控制
```

所以 `09 -> 19 -> 20` 不是一个已经闭合的 NOT/MOV 微程序。至少需要补充地址 `20` 的有效微指令，并确认该微指令结束后回到取指入口 `01` 或讲义规定的入口，而不是回到 00 的空控制字。

## 4. 跳转与 PC 流程审查

### 可直接从 MIF 确认的跳转

主要 `uA` 链为：

```text
01 -> 02 -> 08 -> 01
04 -> 05 -> 06 -> 01
07 -> 0D -> 01
09 -> 19 -> 20h
0A -> 01
0B -> 0E -> 0F -> 15h
0C -> 16h
0D -> 01
0E -> 0F
0F -> 15h
10 -> 12h
11 -> 14h
12 -> 10h
13 -> 01
14 -> 11h
15 -> 01
16 -> 01
17 -> 14h
18 -> 10h
19 -> 20h
1A -> 01
```

其中 `uA=20h` 出现在 19 地址，是一个跳到 20h 的控制流入口，而 ROM 中 20h～3Fh 没有有效微指令；这通常不是普通顺序执行，而是依赖 A9/A8、操作码或外部条件形成的分派地址。若你的硬件确实把 `uA` 直接当作 6 位下一地址，则 19 地址会跳入全 00 区，属于错误；若硬件按讲义设计把它与操作码拼接/选择，则需要在报告或原理图中确认该分派逻辑。**仅凭 MIF 不能把 19 -> 20h 判定为安全。**

### 对指令长度的确定性风险

原程序使用：

```text
IN       1 字节
ADD      2 字节
STA      2 字节
OUT      2 字节
JMP      2 字节
```

若替换后的指令格式变为：

```text
IN       1 字节
NOT      1 字节
MOV      1 字节或另一种格式
```

则原 ADD/STA 入口中的 PC 加 1、取地址字节和微地址回跳都必须重新核对。否则 `12 0A 26 0B ...` 不会按预期解释。当前两个 MIF 没有体现这种修正。

## 5. 建议的修改方向

### 若 NOT 是单字节 `R0 <- ~R0`

- 保留原 ADD 的入口分派地址。
- 在该入口执行：取 R0 到 ALU A 端，选择 NOT 的 ALU 控制码，结果写回 R0。
- 删除取 RAM 地址、RAM 数据送 ALU B 端等 ADD 专用步骤。
- PC 只完成取指后的单字节递增，不要再为 NOT 取操作数字节。
- RAM 程序应把 `12 0A` 改为单字节 NOT 对应的编码，并将后续 MOV/OUT/JMP 从紧邻地址重新排列。

### 若 MOV 是寄存器到寄存器

- 保留原 STA 的入口分派地址，但不要保留 RAM 写使能 `WE=1`。
- 明确源寄存器和目的寄存器，分别选择对应 A/B/C 字段。
- 若 MOV 为单字节指令，去掉取地址字节的微步骤并只递增一次 PC。

### 若 MOV 是 `R0 -> RAM[addr]`

- 可以复用 STA 的大部分数据通路，但必须逐项确认：地址寄存器来自哪里、数据总线来自哪里、`WE` 只在有效写周期拉高一次、写后是否正确回到取指入口。
- 这种定义下 RAM 程序仍可保留双字节 MOV，但机器码助记符与操作码的解释必须在报告中明确写成 MOV，而不能只修改注释。

## 6. 最终判定

| 项目 | 判定 |
|---|---|
| 两个 MIF 的语法 | 通过 |
| RAM 地址范围和填充 | 通过 |
| ROM 地址范围和填充 | 通过 |
| RAM 中 `12`、`26` 是否已作为修改后的机器码使用 | **可以确认**，它们位于两个双字节指令的首字节位置 |
| ROM 是否正确完成 NOT 微操作 | **无法通过**，需确认实际 ALU NOT 控制，且 `09 -> 19` 后的链路不完整 |
| ROM 是否正确完成 MOV 微操作 | **不通过**，`19 -> 20`，但 `20` 当前为 `000000` |
| 复用入口的思路 | 可以，但必须重写入口内的微操作 |
| 指令长度与 RAM 程序一致性 | 若 NOT/MOV 保持双字节格式则通过；若改为单字节则需重排 RAM |
| 19 地址跳到 20h 的控制流 | **确定存在缺口**，20h 当前为 `000000` |

**因此，RAM 的 `12`、`26` 修改位置本身与双字节程序布局一致；当前不能通过的根本原因是 ROM 中 `09 -> 19 -> 20` 的修改控制流没有闭合，地址 20 没有写入 MOV/NOT 所需的有效微指令。NOT 还需要进一步核对实际 ALU 控制字段是否确实为 NOT。**
