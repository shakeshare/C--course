# 计算机组织与体系结构课程设计指导

## 1. 讲义任务的准确理解

讲义描述的是一台采用微程序控制的 8 位基本模型机。CPU 从 RAM 取出机器指令后，不是直接由硬件组合逻辑完成全部动作，而是由微程序控制器按微指令序列产生数据通路控制信号。

讲义中基础模型机已有 5 条机器指令：

| 指令 | 操作码 | 长度 | 功能 |
|---|---:|---:|---|
| `IN` | `0` | 1 字节 | `INPUT -> R0` |
| `ADD addr` | `1` | 2 字节 | `R0 + RAM[addr] -> R0` |
| `STA addr` | `2` | 2 字节 | `R0 -> RAM[addr]` |
| `OUT addr` | `3` | 2 字节 | `RAM[addr] -> OUT` |
| `JMP addr` | `4` | 2 字节 | `addr -> PC` |

本次课设的正确要求是：从原有 5 条机器指令中替换 3~5 条为自行设计的新指令，而不是在原有指令之外额外增加 5 条。指导文档采用一个便于实现和验证的三指令替换方案：保留 `IN`、`STA`，用 `SUB`、`XOR`、`SHL` 分别替换 `ADD`、`OUT`、`JMP`。如果老师要求替换 4 条或 5 条，再在此基础上替换 `IN` 或 `STA`，但必须同时提供新的输入或存储通路，否则测试程序难以闭合。

参考报告采用了 8 条指令 `IN/SUB/INC/XOR/CLR/NOT/STA/SHL`，这已经超出“替换 3~5 条”的任务范围，不能直接作为本课设的最终方案。它仍然可以作为 ALU 微程序写法和实验记录的参考，但提交报告必须删减到规定数量，并明确哪些原指令被替换。

本目录中的两份参考报告实质上是同一套实验内容的 PDF 版和 Markdown 版。Markdown 版适合作为文字底稿，但没有填写实验原理、实验结果和波形分析；PDF 版补充了硬件截图，却仍缺少逐条微指令的解释。因此，下面特别增加了对该八指令方案的审查和修订要求。

## 2. 设计目标与总体方案

### 2.1 建议替换的 3 条指令

| 原指令 | 新指令 | 操作码 | 长度 | 操作定义 |
|---|---|---:|---:|---|
| `ADD addr` | `SUB rs,rd` | `1` | 1 字节 | `R[rd] <- R[rs] - R[rd]` |
| `OUT addr` | `XOR addr` | `3` | 2 字节 | `R0 XOR RAM[addr] -> R0` |
| `JMP addr` | `SHL` | `4` | 1 字节 | `R0 + R0 -> R0` |

这里的 `addr` 是直接给出的 RAM 地址字段。指令格式沿用讲义中的双字节格式：

```text
第一字节：OP-CODE[7:4] + 保留/寄存器字段[3:0]
第二字节：addr[7:0]
```

这里沿用原操作码，因此不需要增加新的操作码分支，只需将原操作码对应的微程序入口改写为新指令入口。`SUB` 使用原指令字节中的寄存器字段，不再读取第二个地址字节。按照讲义格式，`rs` 位于 `[3:2]`，`rd` 位于 `[1:0]`，寄存器编码为 `00=R0、01=R1、10=R2`。例如：

```text
SUB R0,R1  = 11H       ; R1 <- R0 - R1
SUB R1,R0  = 14H       ; R0 <- R1 - R0
XOR [0AH]  = 30 0A
SHL        = 40
```

### 2.2 为什么选择这 3 条

这 3 条指令只要求重写原有 `ADD`、`OUT`、`JMP` 的操作码入口，保留 `IN` 和 `STA` 作为输入与结果存储指令。这样既满足替换要求，又能组成可运行的测试程序。`SUB` 还覆盖了讲义要求的 `rs/rd` 两寄存器数据通路。

- 算术运算：减法、左移；
- 逻辑运算：异或；
- 原有 RAM 取数、结果存储和输入通路的复用；
- 多条指令连续执行和结果验证。

## 3. 必须先确认的硬件事实

在编辑微代码前，先从示例工程和已有 `ADD` 微程序中确认以下内容。不能只凭微代码十六进制数猜测 ALU 控制字段。

1. `A/B/C` 三个字段的具体译码关系。讲义表 1-2 中，A 是输入选通，B 是输出选通，C 是分支/装载控制。
2. ALU 的 `S3..S0`、`M`、`/Cn` 如何映射到 74181 或 `ALU181.VHD` 的运算。
3. `ADD` 微指令使用的 ALU 字段和进位输入设置。
4. 减法是否采用二进制补码：通常为 `A + NOT(B) + 1`。
5. 进位标志在硬件中是“低有效输入/输出”还是普通逻辑电平，尤其是 `/Cn` 和 `CO` 的极性。
6. 微地址 05、06、07、10 等位置是否已经被现有微程序占用，以及指令译码器如何由 `IR7..IR4` 跳转到首地址。

最便宜的验证方法是先复制一份工程，只改一条未使用的操作码分支，让它执行与 `ADD` 相同的微程序。如果该新操作码能正确进入微程序，说明译码分支地址和 ROM 地址组织是正确的；之后再只替换 ALU 字段。

## 4. 取指公用流程与新增指令入口

所有指令共用讲义中的取指流程；其中双字长指令还要继续取地址字节，而寄存器型 `SUB rs,rd` 在取出第一字节后直接执行：

1. `PC -> AR`，同时 `PC + 1 -> PC`；
2. `RAM[AR] -> BUS -> IR`；
3. 通过 `P(1)` 检测 `IR7..IR4`；
4. 根据操作码跳转到对应微程序首地址；
5. 双字长指令再执行一次 `PC -> AR`、`PC + 1 -> PC`，取出地址字节；
6. 地址型指令将地址送入 `AR`，RAM 数据送入暂存器；寄存器型 `SUB` 根据 `rs/rd` 选择两个寄存器；
7. ALU 计算，结果经 `BUS` 写回目的寄存器 `rd`。

因此新增指令的微程序可以复制 `ADD` 的“取地址/取操作数/写回”部分，只替换最后的 ALU 控制字段。

建议在微程序流程图中为新增指令分别画成以下结构：

```text
取指 -> 操作码分支 -> 读取 rs/rd
    -> R[rd] 送 ALU A 端 -> R[rs] 送 ALU B 端
    -> 选择减法 -> ALU-B -> BUS 送 R[rd]
    -> 返回取指
```

## 5. 三条替换指令的微程序设计

下面使用“动作级”描述，真正的 24 位二进制微代码必须根据工程中 ALU 的有效电平和编码表换算。

### 5.1 `SUB rs,rd`

功能：`R[rd] <- R[rs] - R[rd]`。例如 `SUB R0,R1` 表示 `R1 <- R0 - R1`。

该指令不读取第二字节。微程序根据 IR 的 `[3:2]` 和 `[1:0]` 选择源寄存器与目的寄存器，分别送入 ALU。为了便于使用 74181 的减法编码，可令目的寄存器进入 A 端、源寄存器进入 B 端，并实现：

```text
R[rs] - R[rd] = R[rs] + NOT(R[rd]) + 1
```

因此需要：

- 算术模式 `M=0`；
- 将 `R[rs]` 和 `R[rd]` 送入 ALU 的两个输入端；
- 选择“源寄存器加目的寄存器反码”的 `S3..S0` 组合；
- 设置正确的进位输入，使最低位加 1；
- `ALU-B` 有效，将结果送 BUS；
- 目的寄存器 `rd` 的装载信号有效，将 BUS 写回 `R[rd]`。

验证用例：`R0=35H`、`R1=12H`，执行 `SUB R0,R1` 后应为 `R1=23H`，R0 保持 `35H`。还要验证 `SUB R1,R0`，结果应为 `R0=12H-35H=DDH`。

### 5.2 `XOR addr`

功能：`R0 XOR RAM[addr] -> R0`。

取数流程同上，ALU 使用逻辑模式并选择 XOR 功能。

验证用例：`R0=5AH`、`RAM[0AH]=3CH`，结果应为 `66H`。

### 5.3 `SHL`

功能：`R0 + R0 -> R0`，即 8 位左移一位，最高位溢出到进位标志。

该指令是单字节指令，不读取地址字节。微程序可复用 ALU 输入和写回阶段，但需要让 R0 同时作为 ALU 的两个输入端，选择加法运算，再通过 `ALU-B` 和 `LDR0` 写回 R0。

验证用例：`R0=77H` 时，结果应为 `EEH`；`R0=80H` 时，结果应为 `00H`，并根据工程定义检查进位标志。

## 6. 微地址安排建议

讲义明确规定：微程序流程图上的地址用八进制表示，微代码表通常按 6 位微地址存放。因此必须统一“图中八进制地址”和“ROM 地址/表格地址”的表示，避免把 `10` 八进制误当成十进制 10。

可采用以下安排原则：

1. 保留 `00`、`01` 等复位和取指公用入口；
2. 保留操作码 `0`、`2` 对应的 `IN`、`STA` 分支；
3. 将操作码 `1`、`3`、`4` 的原微程序入口分别改写为 `SUB`、`XOR`、`SHL`；
4. 不增加新的操作码分支，也不覆盖控制台 KRD、KWE、RP 的固定微地址；
5. 每条指令最后跳回取指入口，而不是复制一套新的取指流程。

不要直接套用讲义表 1-3 的某一行十六进制微代码。表 1-3 是特定示例工程的编码结果，只有在 A/B/C 字段、ALU 版本和微地址完全一致时才可复用。

## 7. 24 位微指令和 MIF 文件填写方法

讲义给出的 24 位微代码字段顺序为：

```text
S3 S2 S1 S0 M /Cn WE A9 A8 A字段 B字段 C字段 uA5..uA0
```

建议每条微指令按以下顺序填写：

1. 先写“数据通路动作”：哪些单元输出到 BUS，哪些单元从 BUS 装载；
2. 再填写 A/B/C 字段；
3. 填写 RAM 的 `WE`、片选 `A9/A8`；
4. 填写 ALU 的 `S3..S0/M//Cn`；
5. 填写下一微地址 `uA5..uA0`；
6. 将 24 位二进制分组核对，再转换成 MIF 所需格式；
7. 用一个已知的 `ADD` 微指令逐字段反向验证编码顺序。

MIF 文件至少要核对：

```text
WIDTH = 24;
DEPTH = 64;       -- 以工程中 ROM 深度为准
ADDRESS_RADIX = HEX;
DATA_RADIX = HEX;
CONTENT BEGIN
    00 : xxxxxx;
    01 : xxxxxx;
    ...
END;
```

`WIDTH`、`DEPTH` 和地址基数必须以工程中的 LPM_ROM 配置为准；不要因为讲义示例出现 24 位就擅自改动 ROM 深度。

## 8. 三个建议宏程序

### 程序一：算术运算验证

目的：验证 `SUB` 和 `SHL`。

```text
00: IN R0              ; 输入 35H
01: SUB R0,R1          ; R1 <- R0 - R1
02: XOR [0BH]
04: STA [0CH]
06: SHL               
0B: 异或操作数
```

执行前先通过工程已有的寄存器装载路径或临时测试微程序设置 `R1=12H`。输入 `35H` 后，`SUB R0,R1` 应使 `R1=23H`，再由后续指令验证逻辑运算和写回 RAM。由于本方案不再保留 `OUT` 和 `JMP`，结果通过 KRD 或 EAB 读取 RAM 检查。若 `IN` 在你的工程中仍是固定机器码 `00`，报告中应将它写作 `IN`，并在说明中注明输入默认写入 R0；`IN R0` 只是为了表达测试意图。

### 程序二：逻辑运算验证

保持相同输入和 RAM 操作数，分别记录 `SUB`、`XOR`、`SHL` 的输出，便于横向比较 ALU 控制字段。

```text
R0 = 5AH
R1 = 3CH
SUB R0,R1 结果：1EH，写回 R1
XOR 结果需按实际指令定义记录
SHL 结果：B4H
```

### 程序三：组合运算验证

```text
IN
SHL
SUB  [0AH]
XOR  [0BH]
STA  [0CH]
```

该程序可检查多条替换指令连续执行时，R0 写回、下一条取指、PC 自增和 RAM 数据访问是否彼此干扰。

## 9. Quartus II 和实验箱操作清单

1. 备份原始 `b100_c.bdf`、ROM 的 MIF 和工程文件。
2. 在 ROM 初始化文件中加入新增微程序；必要时修改指令译码器的操作码分支。
3. 在 RAM 初始化文件中输入测试程序和数据，注意双字节指令占用连续两个地址。
4. 编译 Quartus 工程，先消除错误，再检查未使用信号和位宽警告。
5. 下载 SOF，复位模型机，确认 `RST` 为高电平时 CPU 才能正常工作。
6. 用 `SWB,SWA=00` 执行 KRD，检查 RAM 内容。
7. 用 `SWB,SWA=01` 执行 KWE，必要时手动改写测试数据。
8. 用 `SWB,SWA=11` 进入 RP，按 STEP 单步执行。
9. 每条替换指令至少记录：`uA`、`IR`、`PC`、`AR`、`DR1/DR2`、`R0`、`BUS`、`RAM`、ALU 输出和 `CO`。
10. 用嵌入式逻辑分析仪观察 `STEP` 上升沿触发后的波形，并对照 LCD 数据判断每个节拍的原因。

## 10. 在 Quartus II 中修改已有基本模型机

本节按讲义常见的 `b100_c.bdf` 工程说明。工程名称可能不同，但基本结构通常是：`.bdf` 负责数据通路，微程序 ROM 使用一个 `.mif`，程序/数据 RAM 使用另一个 `.mif`。

### 10.1 复制工程并确认文件

1. 关闭 Quartus II，把整个基本模型机工程复制一份，只在副本中修改。
2. 确认副本中有 `*.qpf`、`*.qsf`、`*.bdf`、微程序 ROM 的 `*.mif` 和程序 RAM 的 `*.mif`。
3. 常见文件名是 `b100_c.bdf`、`ROM_11.mif`、`5_ram.mif`，但必须以你的工程实际引用路径为准。
4. 先备份原始 ROM/RAM MIF。不要先修改 `.qsf` 引脚配置或 `.bdf` 连线。

### 10.2 找到微程序 ROM

1. 用 Quartus II 打开副本的 `.qpf`，再打开顶层 `.bdf`。
2. 找到微程序控制器中的 `LPM_ROM`，常见实例名为 `rom_a`。
3. 双击 ROM，查看参数中的 `LPM_FILE`，记下实际引用的微程序 MIF 路径。
4. 修改这个被引用的 MIF，而不是修改同目录下未被工程引用的同名文件。

### 10.3 确认原指令入口

先从原 MIF 和 LCD 的 `MC` 显示核对 `P(1)` 分支地址。讲义示例通常把操作码 `0~4` 分到 `IN、ADD、STA、OUT、JMP` 五个入口，常见微地址显示为八进制 `10、11、12、13、14`，但不能直接假设，必须以你的 ROM 和译码电路为准。

本方案沿用原操作码，不增加新分支：

| 原操作码 | 原指令 | 替换后 | 处理方式 |
|---:|---|---|---|
| `0` | `IN` | `IN` | 保留 |
| `1` | `ADD` | `SUB` | 重写原 ADD 微程序 |
| `2` | `STA` | `STA` | 保留 |
| `3` | `OUT` | `XOR` | 重写原 OUT 微程序 |
| `4` | `JMP` | `SHL` | 重写原 JMP 微程序，并删除取地址动作 |

### 10.3A 检查寄存器选择通路

这是实现寄存器型 `SUB` 前必须完成的检查。打开 `.bdf`，确认以下硬件是否存在：

1. `IR[3..2]` 能进入源寄存器选择译码器，控制哪个寄存器输出到 ALU 的源操作数端；
2. `IR[1..0]` 能进入目的寄存器选择译码器，控制哪个寄存器输出到 ALU 的目的操作数端；
3. ALU 结果 BUS 能根据 `rd` 选择写入 R0、R1 或 R2；
4. R1、R2 的复位、时钟和装载信号正常连接；
5. LCD 显示名称使用 `DR1`、`DR2`，不要把两个暂存器写成 `DR0/DR1`。

如果原 BDF 只有固定的 `R0_B` 和 `LDR0`，没有 R1/R2 的选择译码，那么不能只改 ROM MIF。需要在 BDF 中增加寄存器输出多路选择器、目的寄存器写回译码器以及对应控制信号；如果这些控制信号还没有连接到微控制器，则还要修改微控制器 HDL/ROM 字段定义，扩大或重新分配微指令控制位。只有确认这条通路已经存在，才进入下面的 MIF 修改步骤。

### 10.4 把 ADD 改成 SUB

操作码不变，但指令格式改变为寄存器型单字节指令。机器码由 `1`、`rs`、`rd` 拼成：`SUB R0,R1 = 11H`，`SUB R1,R0 = 14H`。

1. 删除原 `ADD` 的取第二字节、PC 自增、AR 装载、RAM 读取和 RAM 数据暂存步骤。
2. 在 BDF 中确认寄存器输出选择能够由 IR 的 `rs`、`rd` 字段控制；源寄存器送 ALU 的 A 输入，目的寄存器送 ALU 的 B 输入。
3. 只改 ALU 运算微指令：`M=0`，选择该工程中 74181 的减法编码，并按 `/Cn` 的有效电平实现补码减法。
4. 使目的寄存器 `rd` 的装载信号有效，将 ALU 结果经 BUS 写回 `R[rd]`。
5. 最后一条微指令跳回公共取指入口。

先验证 `R0=35H、R1=12H` 时 `SUB R0,R1` 得 `R1=23H`，再验证 `00H-01H=FFH`。结果总是差 1 时，优先检查 `/Cn` 的极性。

### 10.5 把 OUT 改成 XOR

操作码不变，因此 `XOR [0BH]` 写成 `30 0B`。

1. 保留原双字节指令的取地址字节、PC 自增和 RAM 读出流程。
2. 不再把 RAM 数据送 OUTPUT，而是将 R0 和 RAM 操作数送入 ALU 的两个输入暂存器。
3. 设置 `M=1`，选择该工程中 74181 对应的 XOR `S3..S0` 编码。
4. 使 `ALU-B` 有效，结果经 BUS 和写回信号送入 R0。
5. 跳回公共取指入口。

### 10.6 把 JMP 改成 SHL

操作码不变，`SHL` 使用单字节机器码 `40`。

1. 删除原 JMP 的 `PC->AR`、取第二字节和 `addr->PC` 微指令。
2. 让 R0 同时作为 ALU 的两个输入，选择加法，即 `R0+R0`。
3. 使 `ALU-B` 和写回 R0 的控制信号有效。
4. 跳回公共取指入口。

如果保留 JMP 的取地址步骤，CPU 会把下一条指令当成跳转地址，这是单字节指令替换双字节指令时最常见的错误。`77H` 左移应为 `EEH`，`80H` 左移应为 `00H`，并检查进位标志。

### 10.7 修改程序 RAM 的 MIF

本方案不再使用 OUT 和 JMP，结果通过 KRD 或 EAB 读取 RAM。由于 `SUB` 是寄存器型单字节指令，测试前必须先通过工程已有寄存器装载路径或临时测试微程序给 R1/R2 设置已知值。测试程序可以写成：

```text
地址  内容  指令
00    00    IN，输入写入 R0
01    11    SUB R0,R1，R1 <- R0-R1
02    30    XOR [0BH]
03    0B    地址字节
04    20    STA [0CH]
05    0C    地址字节
0B    3C    异或操作数
```

若输入 `R0=35H` 且预先设置 `R1=12H`，执行 `SUB R0,R1` 后应为 `R1=23H`。随后 XOR 的源寄存器/目的寄存器定义必须以你的工程方案为准；如果 XOR 仍沿用原 OUT 的双字节地址型数据通路，就不能直接假设它会使用 R1。最终应通过 STA 写回并检查 `RAM[0CH]`。本段示例只用于说明 SUB 的单字节地址推进，不能代替你工程中的完整机器码表。

### 10.8 编译、下载和验证

1. 保存 ROM 和 RAM MIF。
2. 选择 **Processing -> Start Compilation**，先解决所有编译错误和 MIF 路径错误。
3. 打开 **Tools -> Programmer**，选择正确的 USB-Blaster 和 FPGA 器件。
4. 添加新生成的 `.sof`，勾选 **Program/Configure**，点击 **Start**。
5. 复位模型机，释放 RST，设置 `SWB,SWA=11` 进入 RP。
6. 输入 `35H`，按 STEP 单步执行，记录 LCD 上的 `PC、AR、IR、DR1、DR2、R0、BUS、RAM、MC`。
7. 执行到 STA 后切换 KRD 或使用 EAB 读取 RAM，确认 `0CH` 为 `64H`。
8. 出错时先确认 `MC` 是否进入替换后的入口，再按“取地址 -> ALU -> 写回”的顺序定位，不要同时修改 ROM 和 RAM。

> 当前没有你的 Quartus 工程文件，因此不能安全地直接给出最终 24 位十六进制微代码。`SUB/XOR/SHL` 的 ALU 字段必须根据该工程的 `ALU181`、原 ADD 微代码和 74181 编码确定；拿到 `.qpf/.qsf/.bdf/.mif` 后才能逐行生成最终 ROM 内容。

## 11. 故障定位顺序

| 现象 | 优先检查 |
|---|---|
| 新操作码执行后回到错误地址 | `IR7..IR4` 分支编码、微地址是否按八进制理解 |
| 地址字节取错 | `PC -> AR`、`PC+1`、RAM 读使能和 `LDAR` |
| 运算结果总线为 0 或旧值 | `ALU-B`、A/B 输入选通、`DR1` 装载 |
| `SUB` 结果差 1 | 补码减法的进位输入 `/Cn` 极性 |
| `SHL` 结果错误 | R0 是否同时送到 ALU 两个输入端、ALU 加法编码和进位极性 |
| 逻辑运算结果错误 | `M` 模式、74181 的 S 码、A/B 输入顺序 |
| STA/OUT 仍正常但新指令不正常 | 优先比较新指令和 ADD 的微程序，通常是 ALU 字段而不是 RAM 通路问题 |

### 13.2 必须修改或补充的问题

1. **实验目标与实际方案不一致。** 讲义基础部分写的是 5 条指令，参考报告写的是“预计完成八条指令”，但课程要求实际是替换原有 3~5 条。提交报告不能保留八条新设计，应明确替换了哪些原指令以及替换后的操作码。
2. **寻址方式表述错误。** 参考报告沿用了“寄存器直接寻址”的说法，但 `SUB [0BH]`、`XOR [0CH]`、`STA [0DH]` 实际使用的是 8 位 RAM 地址字段，属于直接内存寻址；`rs/rd` 字段在这些简化指令中没有实际参与选择，应明确写出。
3. **指令长度没有标明。** `IN/INC/CLR/NOT/SHL` 是单字节指令，`SUB/XOR/STA` 是双字节指令。测试程序的地址递增正是由这一点决定的，必须在指令表中写清楚。
4. **微程序流程图缺失。** Markdown 版完全没有流程图，PDF 版只保留了“根据功能设计流程图”的文字。至少要画出取指公用流程、8 个操作码分支，以及每条指令的数据流和返回取指路径。
5. **实验原理为空。** 需要补充微程序控制器、IR 高 4 位译码、A/B/C 字段、ALU、BUS、DR1/DR2、AR、PC 和 RAM 的协作关系，不能只放微代码表。
6. **实验结果不完整。** “实验结果”标题下应给出 ROM 内容、RAM 内容、输入值、每条指令的预期值/实测值和最终写入地址。截图必须配文字解释，不能用截图代替结论。
7. **微代码表需要逐字段核对。** 表中 `微指令` 是 24 位十六进制值，必须与 `S3..S0/M/Cn/WE/A9/A8/A/B/C/uA` 分组逐行对应。特别检查 `06`、`07`、`31`、`33`、`36` 等含 ALU 运算的行，并说明为什么它们分别实现减法、加一、异或、清零、取反或左移。
8. **八进制微地址必须声明。** 表中的 `10、11、12...` 是微地址的八进制表示，ROM 查看器中的地址通常显示为十六进制/字节偏移。报告应增加一行说明，避免读者把微地址 `10` 当成十进制 10。
9. **调试步骤有表述错误。** “按 4 次单步键产生 2 个脉冲”这类描述容易造成误解，应分别说明按键次数、STEP 上升沿次数、时序脉冲 T1~T4 和执行的微指令数量。
10. **术语和文字需要统一。** LCD 上的两个暂存器统一写作 `DR1/DR2`；`RO` 应改为 `R0`，`被减数`应改为“减数/操作数”或明确 `D5H` 的角色；“菲浅”“毕竞”等错别字应修正为“匪浅”“毕竟”。
